# AI 单曲推荐升级

2026-10-16。入口是「在线音乐 → 为你推荐 → AI推荐」。填写本次需求，也可手动勾选「参考我的歌单与听歌习惯」；参考范围默认全部用户歌单，支持选择一个歌单。QQ、网易云和 B站分别从自己的真实曲库检索。

## 开源参考

| 来源 | 借鉴的设计 | 本项目接入 |
| --- | --- | --- |
| [Microsoft RecAI / InteRecAgent](https://github.com/microsoft/RecAI/tree/main/InteRecAgent) | 模型理解需求，查询、召回和排序工具执行推荐 | 将本次需求、带权重的偏好转成检索计划，再用平台真实候选限制模型输出 |
| [ListenBrainz / Troi](https://github.com/metabrainz/troi-recommendation-playground) | 以流水线组合候选、过滤和内容匹配；使用收听统计和相似关系 | 复用本机真实收听画像，分阶段整理候选并过滤已有歌曲 |
| [RRF 论文](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) | 合并不同检索列表的排名 | 按歌曲身份合并多个检索方向，采用 k=60 的倒数排名累加；单方向的重复发行只计一次 |
| [MMR 论文](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf) | 平衡相关性和结果之间的重复 | 保留模型相关性主分，降低同歌手、专辑、同曲版本和同一检索方向的集中程度 |

这里应用的是上述项目和论文的设计方法；没有引入其训练模型、训练数据或服务器，也不等同于 QQ、网易云内部推荐模型。Troi 本身不是大模型推荐框架。

## 当前流程

1. **在本机整理偏好。** 只使用「我的列表」可见用户歌单和真实有效收听，不读取隐藏的「我的收藏」或用试听列表的启动顺序充当偏好。与软件推荐共用近30天、7天半衰期及单日贡献限制：完播和复听优先，有效时长补充，主动快跳减分。正向参考最多24首，同歌手最多2首；冷启动在各参考歌单之间轮换抽样。还可提供最近一段收听方向最多6首、常跳过的歌曲最多6首。原始会话、时间戳和完整记录留在本机。
2. **模型制定互补检索计划。** 本次需求优先于历史口味。最多6个方向，具体歌曲最多4个，并结合歌手或风格检索扩大候选。同一歌手最多两个方向；纯具体歌曲计划会补充已知歌手的检索方向。明确的单曲建议只作为待核对目标。
3. **查真实曲库。** 每方向只取第一页，最多20条；QQ、网易云并发最多2，B站串行且遇限流立即停止。检索阶段满30秒后不再安排下一批；在途请求仍受原有单次超时和取消控制。具体单曲必须歌名及可信歌手均匹配，搜不到时不使用无关首条搜索结果替代。B站保留时长、合集、教程等单曲筛选。
4. **本地融合与排除。** 多方向结果按 RRF 合并；排除所有用户歌单已有歌曲，包括没有选作参考的歌单、未抽样到的歌曲以及跨平台同名同歌手记录。还过滤页面反馈、全局不喜欢、已展示和可选的近一天有效收听歌曲。启用画像时，对重复快跳形成的强负反馈也进行过滤。最多40首真实候选进入模型排序。
5. **模型排序并允许拒绝。** 只向模型发送候选 ID、歌名、歌手、专辑、时长、检索词和已同意的偏好摘要。模型只能选择真实候选 ID，也可明确排除不符需求的歌曲；排除优先，不会在补齐结果时复活。检索词不是音频证据，不能据此声称听过音频或查询过歌词。
6. **按相关性与多样性展示。** MMR 保留模型相关性主分，并依据元数据控制重复；不再对模型结果重新执行旧的关键词打分。显示最多20首，余下候选供「换一批」使用。排序失败会提示并退回真实候选的本地排序；计划失败、取消或没有合适候选时保留已有结果。

## 调用与缓存

- 沿用现有兼容模型服务配置；需要用户的模型服务或本机兼容服务，不新增嵌入 API、推荐账号或后台服务依赖。
- 一次手动生成最多2次模型调用、6次平台歌曲检索操作。B站游客身份初始化和屏幕内未知歌手的原有补全机制独立复用，不能把检索次数等同于全部 HTTP 请求数量。
- 「换一批」、切换平台、打开页面及重启不调用模型；没有新增轮询或持续后台计算。
- 未勾选偏好参考时，不向模型发送个人种子、近期或跳过摘要；仍可在本机读取歌单排除已有歌曲。仅开启「避开近一天」时读取有效收听做本地过滤。
- 缓存仍使用三平台分开的40候选、20显示 ID和有限展示记录。算法版本升级为2，旧结果丢弃，保留偏好、同意状态和软件推荐共用的不感兴趣反馈；旧 `love/default` 参考迁移到全部可见用户歌单。
- 新缓存只额外保存有限的相关性分数和 `q0…q5` 方向标记，不保存完整模型计划、完整收听摘要、模型凭据、音频地址或歌词；用户填写的本次需求仍作为本机偏好保存。

## 验证边界

153项回归检查通过，主进程与界面类型检查、AI页面生成脚本类型检查、Vue模板、Less/CSS modules、相关代码规范和三种语言检查通过。覆盖真实歌曲核对、跨平台已有歌曲排除、完播/复听优先、快跳负反馈、个人画像关闭、跨歌单抽样、多方向融合、多样性排序、模型拒绝、六次检索与并发限制、检索时间预算、取消和过时任务、缓存迁移与字段白名单。

模型请求使用隔离的模拟响应验证，未自动调用用户付费模型服务，也未自动播放歌曲或写入人工收听记录。测试能验证流程、预算及过滤约束；推荐是否更符合个人口味，还需要用户实际生成和收听后判断。元数据匹配不保证平台音源始终可播放，艺术家不明确的 B站结果也可能无法通过具体歌曲核对。
