# Bilibili 歌单

在左侧「在线音乐 → 音乐推荐 → bili音乐推荐」，可直接浏览热门、最新音乐合集。「音乐推荐」分组同时包含企鹅音乐推荐和网易云推荐，可展开、收起并记住状态。B 站推荐支持华语、日语、欧美、古风、纯音乐、学习和睡前分类，以及上一批、换一批和刷新。卡片仅保留可展开为多首歌曲的多 P 视频或 UP 主合集，并显示实际曲目数；单 P 视频不会混入歌单卡片。旧版 B 站发现页链接会自动跳转到独立页面；普通「歌单」的来源和分类单独保留。

发现页自动搜索并检查真实视频详情，最多取一页 20 个候选、2 个详情请求并发。每找到可用合集就立即显示卡片，其余候选继续加载；点击卡片即可打开，无需等整批完成。同一分类刷新时保留已有卡片，新结果逐步替换。切换分类、来源或离开页面会取消旧请求，过时的进度回调不会覆盖新页面。

匿名访客信息请求超时设为 5 秒，搜索请求为 8 秒，单个详情请求为 5 秒；详情检查阶段最多等待 20 秒。单个请求失败时继续显示其他可用合集；达到等待上限时取消未完成请求，并提示可刷新重试。遇到 B 站限流停止后续检查，保留已找到的卡片并提示限流；没有可用结果时显示错误。

完整结果缓存 10 分钟，最多保留 12 批；跨分类和排序共用最多 128 个已检查的视频记录，记录只保留合集卡片数据或已确认的非合集状态，不保存完整视频详情。刷新会重新检查，部分失败的批次不会伪装成完整缓存。缓存过期在访问时处理，不添加后台轮询。

## AI 推荐

在 B 站歌单页选择「AI推荐」会打开独立的「为你推荐」页面并选中 bilibili，当前以单曲推荐为主，也支持 QQ 和网易云。新入口支持参考指定歌单、调整探索程度、避开最近播放和「不感兴趣」，见[三平台单曲推荐](track-recommendations.md)。以下说明保留的旧版 B 站 AI 歌单流程；旧版带 `sortId=ai` 的页面链接仍可使用。

首次使用先打开「AI推荐设置」，填写 Chat Completions 兼容服务的 API 地址、模型名称和 API Key。基础地址会自动补全 `/chat/completions`，也可以填写完整接口地址。远程服务使用 HTTPS；本机 `localhost`、`127.0.0.1`、`::1` 的 HTTP 兼容服务也可以使用，免认证本地服务可不填 Key。

配置保存在本机独立的 `ai_recommendation.json` 中，Key 由 Electron `safeStorage` 加密后保存，主进程不向页面返回 Key。Key 输入留空时沿用同一服务已有的 Key；切换服务域名时不复用旧 Key。可以通过「清除配置和Key」删除配置。

保存配置不会调用模型。「保存并测试连接」会发起一次小请求；「生成推荐」最多调用模型两次：先生成最多 2 个检索主题，搜索并验证 B 站实际存在的歌单，再让模型对最多 20 个真实候选排序。未知或重复的候选 ID 会被丢弃；排序失败时保留真实搜索结果，并提示当前使用搜索顺序。模型服务可能按用量收费，费用由用户配置的服务决定。

AI 推荐只在手动点击时生成，支持取消，单次模型请求超时为 60 秒，不自动重试付费请求。返回歌单详情或切换页面不会重新调用模型。本次运行内保留上次生成的结果；重新启动后需要重新生成。热门和分类浏览无需模型配置。

## 打开已有歌单

在「bili音乐推荐 → 打开歌单」粘贴 B 站链接或数字收藏夹 ID。「歌单 → 打开歌单」也可粘贴 B 站链接，软件会自动识别平台；只有收藏夹 ID 时，在下拉框选择「哔哩哔哩」再输入数字。

支持以下内容：

- 公开收藏夹：带 `fid` 的空间链接、`/medialist/detail/ml123`、`/list/ml123`、`/playlist/pl123`，以及纯数字收藏夹 ID。
- UP 主合集：`space.bilibili.com/用户ID/lists/合集ID?type=season`、旧版 `channel/collectiondetail?sid=合集ID` 和带 `business=space_collection` 的播放链接。
- UP 主视频列表：`lists/列表ID?type=series`、`www.bilibili.com/list/用户ID?sid=列表ID`、旧版 `channel/seriesdetail?sid=列表ID` 和带 `business=space_series` 的播放链接。
- 多 P 视频：视频链接、BV 号或 av 号，每个分 P 显示为一首歌曲。
- `b23.tv` 分享短链接和包含链接的分享文案。

点击「收藏」导入到「我的列表」，之后通过列表的刷新功能重新拉取。收藏夹和合集中的每个视频对应一首歌曲，播放该视频的第一 P；要导入全部分 P，请打开对应视频链接。

收藏夹、合集和视频列表会加载全部分页。已删除或失效的视频会跳过；请求失败会中止导入或刷新，保留本地已有内容。空收藏夹会正常显示为空。

B 站音频使用内置接口播放，无需导入自定义音源。播放时获取 DASH 音频流，分 P 通过 `BV号_分P序号` 区分。标准音质档使用接口返回的可用 AAC 音频，实际码率由 B 站提供；下载保存为 `.m4a`。每次播放重新获取带有效期的音频地址，优先使用接口提供的常规 CDN 备用地址，避免区域节点连接超时；加载失败时沿用播放器现有的刷新重试流程。

## 歌手和歌词

视频 UP 主单独保存在曲目元数据中；歌单卡片的作者仍表示 UP 主。歌曲的艺术家先从分 P 标题、歌名书名号和歌手合集标题识别。在线歌单和「我的列表」会自动补全当前屏幕内艺术家缺失的 B 站歌曲：等待期间显示「识别中…」，无法确认时显示「未知歌手」，无需先播放每一首歌。

自动补全只处理可见行，全局同时处理最多 2 首歌曲，短暂延后启动以减少快速滚动时的请求；已有歌手的歌曲不额外查询。滚出屏幕、离开页面或窗口隐藏时取消未完成行的订阅和后续排队任务，已发出的少量请求可以完成并供缓存复用。不自动扫描整张歌单，不获取音频或歌词。补全结果会更新在线歌单缓存；「我的列表」还会保存匹配关系，避免重复查询。

识别先使用内置的企鹅和网易搜索接口，匹配失败才补查酷我，按歌名、歌手线索、时长和 Live／DJ／伴奏版本筛选。没有歌手线索时，要求至少两个平台提供相符的歌手和时长，并排除相近的同名候选。播放时沿用该匹配关系获取时间轴歌词，同时更新播放器和系统媒体信息，音频仍播放原来的 B 站 BV 和分 P。

这部分不需要 AI 配置或额外 API Key。每个平台最多搜索 25 个候选，搜索等待上限 15 秒；最多保留 64 个搜索结果，成功结果缓存 10 分钟，未匹配结果缓存 1 分钟。播放和列表补全共用匹配缓存，不添加定时轮询。旧版本已导入的曲目会在列表补全或播放时自动拆分 UP 主和歌手信息，无需重新导入；切歌时同时清空普通、翻译、罗马音和逐字歌词，避免残留上一首内容。

同名歌曲、特殊翻唱、剪辑或明显变速的视频可能无法自动确认歌手或匹配歌词，此时保留未知歌手，不自动套用其他版本。已有本地歌词在搜索失败时仍可显示。

当前支持无需登录即可访问的公开内容。私密收藏夹、需要登录的视频以及 B 站限流会显示对应提示。此入口不包含 B 站账号登录或整个账号的收藏夹浏览。
