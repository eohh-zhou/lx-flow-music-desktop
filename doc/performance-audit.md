# 侧栏与内存检查（2026-10-18）

本次优先检查启动、侧栏歌单、推荐、在线浏览、音效和频谱这些长期驻留路径。结论是：新增功能确实有不必要的整库读取，部分浏览和音效缓存也缺少上限。已直接修改这些路径；没有通过定时强制 GC 或清空正在播放的列表来降低数字。

## 本次修改

| 路径 | 原来的问题 | 现在的行为 |
| --- | --- | --- |
| 侧栏 | 为显示一张封面，调用 `getListMusics` 读取整个歌单；展开时对所有歌单同时读取，歌曲同时驻留渲染进程和数据库 worker | 新增第一首歌曲查询，数据库使用 `LIMIT 1`；不写入完整歌单缓存。最多两个并发任务，侧栏/分组收起或窗口隐藏时暂停后续任务 |
| LX / AI 推荐 | 读取“我的列表”时也进入完整歌曲缓存，连封面、音质和其他元数据一起保留 | 只读 ID、歌名、歌手、平台及 B 站匹配歌曲的身份；临时摘要用于偏好计算与排重，不写入完整歌单缓存 |
| 在线歌单 | 每个浏览过的页面一直留在 Map 中 | 保留最近 24 页，且缓存内合计最多 3,000 项；超过单个容量的大页仍正常显示，但不加入缓存 |
| 排行榜 / 歌手 | 历史访问记录没有容量上限 | 排行榜最近 16 页 / 2,000 首，歌手资料最近 24 项；命中会更新访问顺序 |
| 混响音效 | 所有解码过的 AudioBuffer 长期保留；旧请求可能晚到并覆盖新预设 | 最多缓存 3 个预设 / 24 MiB，关闭效果释放已有缓存；只有当前请求能应用结果，加载完成前不写入尚未创建的增益节点 |
| 频谱 | 多次收到播放事件可以叠加动画循环，平均频率跨帧累加 | 保持单一动画循环、复用采样数组、逐帧重置均值；隐藏、暂停、停止、销毁时停止绘制 |
| 页面请求 | 上一页请求失败时可能清空已经切换到的新页面 | 失败处理先核对当前页面，过期请求不会覆盖新页面 |

完整曲库仍参与已有歌曲排除，包括未选中的歌单和 B 站已匹配的歌曲。推荐输入精简不会把歌单外发现变成只抽取歌单里的歌。未完整加载的歌单在删除、清空、排序或修改歌曲后也会通知封面和推荐更新。

侧栏开关位于顶部返回按钮左边；状态保存在 `common.sidebarCollapsed`，下次启动恢复。收起后内容区扩宽；使用左侧窗口按钮布局时，关闭/最大化/最小化按钮移到顶部，恢复入口保持可见。侧栏使用隐藏方式保留导航状态，不把“收起侧栏”本身作为显著释放内存的措施。

缓存上限约束的是额外缓存引用。当前显示页面、播放队列、正在使用的卷积节点及尚未结束的请求仍可持有自己的数据；页面缓存的歌曲数量也不等同于精确字节数。

## 测量与对照范围

修改前对正在运行的安装版做了一次 10 秒进程采样。7 个进程的工作集相加约 **814 MiB**，private bytes 相加约 **813 MiB**；其中主界面渲染进程工作集约 200 MiB。采样期间没有观察到较高 CPU 使用率。

工作集相加可能重复计算共享页；private bytes 是私有提交量，不是实际物理内存。该采样没有固定播放状态、桌面歌词和已浏览页面，也没有同条件运行用户所说的原版。因此这些数字仅作问题排查基线，不能据此宣布优化降低了某个百分比。后续应使用同一歌单、相同窗口大小/背景/音效/歌词设置，分别比较启动后、播放 10 分钟后、浏览 30 个歌单后及最小化后的稳定值。

源码对照使用 [LX Music 上游提交 ad95d509](https://github.com/lyswhut/lx-music-desktop/tree/ad95d5091c9ed689fa72b5e5c849df65f5a679ce)，版本 2.12.6；该提交的 Electron 为 42.11.6，本项目为 40.9.2。上游侧栏没有本项目这段逐歌单读取全部歌曲以获取封面的逻辑。用户机器上原版的具体版本尚未确定，不能把差异直接归因于 Electron 版本。

检查和优化方式参照 [Electron 性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)，内存指标区分参照 [Electron process 文档](https://www.electronjs.org/docs/latest/api/process)。

## 验证

`npm run test:regression` 包含数据库真实 SQL、轻量读取不污染完整缓存、跨平台歌曲排除、封面并发/隐藏/销毁/过期响应、缓存淘汰、页面请求竞争、频谱生命周期和音效预设竞争测试。主进程与渲染进程分别进行生产编译；界面使用独立数据目录检查，不读取安装版账号或改动真实播放历史。

最终结果：184 项回归测试通过，完整 ESLint 检查通过，主进程与渲染进程生产编译通过。界面验证覆盖 1380 / 1040 像素窗口、收起/展开、重启后恢复收起状态，以及左侧窗口控制按钮布局。独立测试窗口已退出。构建仅提示 Browserslist 的兼容性数据库需要更新，未产生编译错误。

## 后续值得做的功能

1. **播放失败诊断**：区分音源解析、音频下载、解码和歌词匹配阶段，提供单独重试。针对偶发“加载慢”，比统一显示加载中更容易定位。
2. **本地听歌统计与偏好管理**：查看最近完播、重复播放、主动跳过如何影响推荐，允许清除指定时间段的统计。沿用现有播放事件，避免新增后台轮询。
3. **按需资源诊断页**：打开页面时查看各进程内存、缓存项数和在途任务，帮助比较安装版与开发版。现有设置已有磁盘缓存清理入口，不需要再增加一个同功能按钮。

后续仍可检查大歌单页面和播放队列的驻留策略、壁纸解码/GPU 占用、音源脚本进程与桌面歌词进程。这些需要同条件实测后再改，不能一概通过关闭加速、销毁播放器或清除整份歌单缓存处理。
