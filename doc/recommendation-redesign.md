# 为你推荐：LX推荐与 AI 推荐

更新日期：2026-10-18。软件推荐现已更名为「LX推荐」，每首参考歌在整份结果中最多带出2首。两种模式改为单列歌曲列表，一次列出本次全部合格结果，移除「换一批」。基础收听统计和 AI 偏好增强已实现。AI 的多方向检索、受限排序与调用预算详见 [AI推荐升级说明](./ai-recommendation-upgrade.md)。

算法升级及验证见 [平台与开源推荐算法调研](./recommendation-algorithm-research.md)：公开歌单关联候选、近期上下文和 MMR 多样性重排均已接入开发版。

偏好来源已按当前使用方式修正：以「我的列表」中的自建、导入歌单为基础，再结合实际收听行为；不依赖独立的「我的收藏」列表。

结果只推荐「我的列表」所有用户歌单之外的歌曲。歌单用于分析喜好，不直接混入推荐候选；未选作参考的歌单也参与已有歌曲排除。近期完播、反复有效播放是主要正向信号，实际收听时长辅助，主动快跳减分。

## 1. 入口与功能边界

独立的「为你推荐」以单曲为主，一级切换改为「LX推荐 / AI 推荐」。软件模式中 QQ 音乐、网易云、bilibili 是检索候选歌曲的曲库，放到「曲库范围」筛选中，默认全部；AI 模式保留原有平台选择。

现有「音乐推荐」分组内的三个平台入口继续提供平台自身的推荐。独立页去掉「平台每日推荐 / B站音乐热门」按钮，软件推荐不再调用平台个性化推荐接口作为最终结果。

```text
在线音乐
  搜索
  为你推荐
    [ LX推荐 ]  [ AI 推荐 ]
    曲库范围：全部 / QQ 音乐 / 网易云 / bilibili
  音乐推荐
    企鹅音乐推荐
    网易云推荐
    bili音乐推荐
```

两种模式分别保留结果，软件推荐的各曲库范围也分别缓存。切换先显示对应缓存；需要补充新候选时，由「更新推荐」触发。软件页只保留筛选、歌单范围、更新与歌曲操作，去掉重复标题、算法说明、收听状态段落、更新时间和底部说明。歌曲行展示序号、封面、歌名、歌手、时长和操作，推荐理由作为次要信息，混合曲库时额外显示平台标签。

视觉进一步改为透明工具栏与双列歌曲行，移除筛选面板和单曲的大块白底。封面、淡序号和细分隔线建立层次；悬停或键盘聚焦时显示行高亮与操作按钮，触屏直接显示按钮。文字使用主题色阶保证背景图上的可读性。

| 模式 | 主要依据 | 用户操作 | 生成方式 |
| --- | --- | --- | --- |
| LX推荐 | 我的列表中的歌单、实际收听、重复播放、主动跳过、明确反馈 | 更新推荐；可选贴近喜好 / 均衡 / 探索 | 本机生成偏好、检索真实候选、本机评分排序 |
| AI 推荐 | 手动开启后共享带权重的歌单与真实收听摘要 | 如「今晚想听节奏慢一点的华语歌」，手动生成 | 多方向检索真实曲库，候选受限排序和多样性重排 |

软件推荐用于发现歌单之外的歌曲。按所有用户歌单的完整歌曲 ID、歌名和可靠歌手信息排除同曲，包括跨平台重复和可确认的 B 站曲库匹配记录；排除范围不限于画像抽样。元数据不完整时对相同标题保守过滤。候选不够就显示实际数量，网络失败时也不拿已有歌单歌曲补齐。

参考歌单默认使用「我的列表」中的全部用户歌单，可改为勾选一个或多个，也可排除睡眠、白噪音等不希望影响日常推荐的歌单。试听列表单独提供近期播放线索，临时播放队列不作为用户歌单。歌曲卡片的加入操作仍然是选择一个现有歌单。

## 2. 重构前的数据基础与问题

已核对以下路径：

- `src/renderer/core/useApp/usePlayer/usePlayHistory.ts`：歌曲开始播放时记录一次，切歌后允许再次记录。
- `src/renderer/store/list/action.ts` 的 `recordPlayMusic`：把歌曲加入试听列表或移到顶部，同一首歌在列表内去重。重构前的试听列表只有近期播放顺序，没有真实收听时长、播放次数、完播率和快跳统计；本轮新增独立的统计模块。
- `src/renderer/core/useApp/usePlayer/usePlayProgress.ts`：有时间更新和断点续播位置。断点位置不能当作累计收听时长，拖动进度也不能当作听过。
- `src/renderer/components/layout/Aside/NavBar.vue` 和 `src/renderer/views/List/MyList/index.vue`：当前「我的列表」显示试听列表与 `userLists` 中的用户歌单，没有独立显示底层保留的 `loveList`。
- `src/renderer/utils/recommendation/profile.ts`：当前只从近期歌曲和一个选定歌单抽取参考歌曲。初版推荐页仍提供 `love` 选项，且 `session.ts` 把它设为默认参考；重构时改为可见用户歌单的范围选择。
- `src/renderer/views/Recommendations/index.vue`：当前一级按平台切换，非 AI 按钮使用 `platformTracks`，确实和已有平台入口重复。

现有用户歌单可以立即用来建立初始偏好；旧试听列表只能作为较弱的近期线索。新增统计从功能启用后开始累计，历史缺失的时长和次数保持未知。

## 3. 本地偏好怎样形成

### 行为信号

| 数据 | 推荐中的作用 | 处理方式 |
| --- | --- | --- |
| 我的列表中的参考歌单 | 初始与长期偏好的基础 | 自建、导入歌单均可参与；同一歌曲跨歌单去重，限制单一歌手和大歌单的贡献 |
| 后续加入参考歌单 | 正向更新 | 增量更新偏好；整张歌单导入不等同于逐首主动喜欢 |
| 实际收听时长 | 正向 | 按歌曲时长归一化，并限制单首贡献，避免长音频占满画像 |
| 完播、多次有效收听 | 较强正向 | 一次会话和单日贡献设上限，循环播放不会无限放大分数 |
| 最近一段时间的变化 | 短期偏好 | 近期记录与长期偏好分别计算，旧信号随时间衰减 |
| 主动很快切到下一首 | 弱负向 | 多次出现才逐步降权；切上一首不直接算不喜欢 |
| 不感兴趣、现有屏蔽规则 | 强负向 / 排除 | 与已有不喜欢列表共同过滤，支持恢复反馈 |
| 缓冲、断流、播放失败 | 不提供喜好判断 | 不计为主动跳过 |

初版用可解释的轻量评分。权重属于可调整的工程参数，不宣称是已经训练出的最佳权重。

歌单决定初始推荐方向；有足够真实收听数据后，用常听、完播和跳过来调整这些方向。新用户无需使用额外的收藏功能，也无需先积累多天记录才能生成第一批推荐。

### 时长与完播的口径

复用播放器现有时间更新、播放、暂停、等待、结束和切歌事件。只有处于真实播放状态、媒体进度合理前进的区间才贡献收听时长；结合单调时钟和播放速度检查进度变化。

- 暂停、缓冲、加载、系统休眠和切歌时断开计时锚点。
- 拖进度、断点恢复、故障恢复中的自动跳进度不累计为收听。
- 分开记录真实收听秒数与歌曲内容覆盖比例。覆盖区间求并集，反复听开头不会被误认成完整听完。
- 可以从「实际听够 30 秒，或覆盖歌曲的 90%」作为有效收听初始门槛，再根据使用情况调整；完播以覆盖比例为主，不能只看是否触发 ended。
- 主动快跳必须有明确的用户切换来源。现有 `playNext(isAutoToggle)` 可以辅助区分自动切歌，不能把所有 `musicToggled` 都当作用户跳过。
- 程序只能观察播放器运行情况，无法确认用户是否认真听。睡眠歌单、长音频和单曲循环因此需要限权，并允许排除相应歌单。

### 画像内容

画像保存偏好歌手、代表歌曲、近期变化、有效收听的置信程度和排除项。歌名、歌手、专辑可以直接利用；风格、语言等标签仅在有可靠曲库元数据或用户明确选择时参与评分。

歌单采样按歌单与歌手分散选取，避免只读每张歌单最前面的歌曲。同一首歌放入多个歌单不会被重复累加成多次喜欢。参考范围保存为「全部用户歌单」或「选定歌单 ID + 排除项」；新增、删除歌单和歌曲变动时增量失效相关缓存，不在每次播放时重新扫描所有歌单。

B 站 UP 主继续作为上传者保存，不能用作歌手偏好。歌手尚未可靠识别的记录降低匹配权重，不把 UP 主名称带入画像。

## 4. 软件推荐怎样找到歌单之外的新歌

推荐分为「召回候选」和「本地排序」，不能只对已有歌单随机抽样。

```mermaid
flowchart LR
  A[我的列表中的参考歌单] --> P[本地偏好摘要]
  B[实际收听与反馈] --> P
  P --> Q[选择少量检索方向]
  Q --> C[QQ / 网易云 / B站真实候选]
  C --> R[本地匹配评分与去重]
  P --> R
  R --> D[歌手多样性与新鲜度调整]
  D --> O[推荐单曲与推荐依据]
```

候选来源按信息可用程度逐步扩展：

1. 已偏好歌手的其他作品：复用现有歌曲搜索，不直接拉平台每日推荐。
2. 参考歌单中的其他偏好歌手的作品。歌单本身只提供偏好，不直接作为推荐结果；一张很大的导入歌单不能决定全部方向。
3. 第一页没有符合条件的歌单外歌曲时，在本轮请求预算内继续查第二页；按平台顺序保留部分可用结果。
4. 已接入匿名公开歌单共现：检查歌单与代表歌曲的真实重叠，再发现其他歌手的新歌；QQ / B站通过歌曲检索核对后转换到所选曲库。不调用平台每日推荐。
5. 当前仍主要利用歌曲元数据与有限公开歌单关系，不宣称已经识别音乐风格或分析音频。

本地排序综合偏好匹配、关联置信度、近期连续收听方向和明确反馈，再通过 MMR 分散歌手、专辑、版本及关联上下文。贴近喜好 / 均衡 / 探索同时调节检索通道和重排，参数继续根据真实反馈调整。

关联检索优先分给最多四首不同歌手的代表歌曲，候选解析与排序同时分散推荐锚点。所有探索档位下，每首参考歌在整份结果中最多带出2首，歌手搜索和关联候选共享配额；只有一个方向时仍保留上限。同一公开歌单也限制贡献，均衡最多5首。成功更新后轮换部分真实参考歌，并排除上一份完整列表及近期已展示歌曲；候选不足时显示实际数量。

跨平台先按平台 ID 去重；有可靠歌名、歌手和版本信息时再合并同一录音。Live、翻唱、重制等版本保留区别；无法确认时不强行合并。推荐结果仍沿用各平台原有播放逻辑，检索到歌曲不等于已经验证可播放。

推荐理由直接来自排序依据，例如「你最近多次听完蔡依林的歌曲」「来自你选定的华语歌单」。尚无完播统计时不用完播类文案。候选不足时显示实际结果，不用无关热门填满列表。

## 5. AI 推荐怎样配合

AI 已接入同一真实收听画像；模型配置和手动参考开关沿用，调用仍由用户手动触发。

AI 模式共用画像计算、平台歌曲搜索、已有歌曲排除和反馈层，额外理解自然语言需求、提出搜索方向和调整排序。

1. 用户填写需求。可继续沿用现有「参考我的听歌偏好」开关；开启后才把压缩后的偏好摘要用于模型请求。
2. 第一次模型调用得到最多6个互补检索方向，软件去选定曲库检索真实歌曲；具体单曲须核对歌名和歌手。
3. 第二次模型调用仅对已有候选 ID 排序，也可明确排除不符需求的歌曲；歌名、歌手、来源等元数据保持来自真实结果。
4. 未知 ID、重复结果丢弃，模型未选中或明确排除的歌曲不会补回；模型评分和顺序构成相关性主分，再做 MMR 多样性调整，筛选失败时明确提示并使用本地候选。AI 模式的结果与软件模式缓存分别保存。

摘要只需代表歌手、少量参考歌曲和相对偏好，不必上传逐条播放日志、精确时间、原始累计秒数或账号 Cookie。AI 推荐不按每首歌曲、每次切歌自动调用，继续由手动生成触发。

AI 与软件模式均使用可见用户歌单，分别保存参考范围；AI 默认全部，也可选一个歌单。切换模式不读取隐藏的收藏列表。是否把这些偏好交给模型，仍由 AI 模式中的参考开关控制。全部用户歌单的已有歌曲排除在本机执行。

## 6. API、资源与存储

| 环节 | 网络 / API | 运行方式 |
| --- | --- | --- |
| 收听统计、画像计算 | 不需要网络和模型 API | 本机事件驱动、增量更新 |
| 软件推荐找新歌 | 需要曲库检索接口，不需要模型 API | 按需复用已有 QQ / 网易云 / B站搜索 |
| AI 推荐 | 需要已配置的模型 API，以及曲库检索 | 手动触发，正常流程最多两次模型调用 |
| 打开页面、切换曲库 | 读取已有候选缓存时无需新请求 | 本次合格结果完整展示，候选不足时可手动更新 |

建议第一版采用以下预算，后续测量实际延迟和内存后再调整：

- 不增加每秒轮询；时间更新回调只更新当前会话内存数据。
- 切歌、暂停等节点批量提交；连续播放期间也可利用现有时间回调在达到保存间隔时提交检查点。写入使用会话 ID 和序号去重，避免重复累计；异常退出最多损失一个检查点间隔。
- 行为数据接入现有主进程数据库 worker 和 SQLite 迁移流程，每个播放会话只保存一行汇总，检查点按版本覆盖；保留 90 天、查询最多 5000 行，不保存每秒原始日志。画像计算时按歌曲、日期限权。
- 打开页面检查本地已有歌曲后显示缓存；手动更新时读取参考歌单的分散抽样和会话汇总，不在每次播放时扫描歌单。歌曲加入用户歌单后同步更新排除项。
- 一轮软件推荐的歌曲搜索、歌单上下文和跨曲库核对共用并发 2 的队列，最多 22 个检索操作，30 秒后不再启动新操作；在途请求按 8～12 秒超时或取消结束。B站首次可能额外获取一次共享的游客身份。初次生成可临时预览先到的合格结果，取消时清除预览；已有结果在更新成功前保留。每个曲库范围缓存最多 60 个筛选候选，完整显示满足两首配额等筛选的结果。
- 匿名歌单上下文每轮最多 4 张，每张读取最多 100 首的曲目信息；公共缓存仅 16 张歌单和 32 项搜索结果，6 小时后按需过期，不保存音频与歌词。
- 切换模式、离开页面或取消时中断剩余任务；错误不自动连续重试。
- 复用已有 B 站可见歌曲的歌手补全队列，不为建立画像扫描全部视频详情、歌词或音频。

软件推荐可在无模型配置时使用。离线时可查看经过本地歌单排除检查的缓存结果，生成新的在线候选需要网络。推荐请求不预先下载音频，也不逐首预取播放地址。

## 7. 对现有实现的调整顺序

| 顺序 | 改动 | 对应位置 |
| --- | --- | --- |
| 1 | 新增真实收听会话、统计与数据库迁移 | `usePlayHistory.ts` / 播放器事件、`src/main/worker/dbService`、公共类型与 IPC |
| 2 | 以用户歌单建立增量画像与本地检索方向、排序 | `utils/recommendation/profile.ts`、`userLists`、新增软件推荐引擎；复用 `providers.ts` 的 `searchTracks` |
| 3 | 页面改为两种模式、参考歌单范围、曲库筛选、结果来源与依据 | `views/Recommendations/index.vue`、多语言和模式独立缓存 |
| 4 | AI 使用同一画像，保留手动授权的参考开关 | `utils/recommendation/engine.ts`、主进程 AI 模块与公共上下文类型 |

以上4项均已完成。AI 的具体实现、开源参考和验证范围见单独的升级说明。

旧缓存中的 `platform` 结果不能更名为「软件推荐」。升级缓存版本，单独处理旧 AI 结果和偏好；新增软件推荐缓存从空开始。已有平台推荐入口、歌单和音乐库继续按原方式使用。

旧版单歌单偏好若指向现存用户歌单，可迁移为选定范围；旧默认值 `love` 或已不存在的歌单改为全部用户歌单。没有用户歌单时使用已有真实收听信号，或提示添加、导入歌单，不回退到隐藏列表。

两种推荐共用的行为画像使用最近 30 天数据，时间衰减半衰期 7 天；无有效播放时仅参考歌单，出现有效播放后行为权重从约 68% 逐步提高到 85%。单日每首歌的完播、重复和时长贡献均有限额，避免循环播放无限放大。

## 8. 验收重点

- 正常播放、暂停、缓冲、倍速、休眠、拖动、恢复进度、重复区间和单曲循环的计时正确；自动播放失败不产生负面偏好。
- 默认以全部用户歌单起步，支持多选和排除；不要求存在或使用「我的收藏」。新增、删除歌单后范围与缓存正确更新。
- 导入大歌单不会压过其他参考歌单和真实收听；同一歌曲跨歌单去重，历史缺失信息不伪造。
- 软件推荐路径不调用模型 API 或平台每日推荐；账号未登录时仍可使用公开曲库搜索。
- 推荐尊重全局不喜欢和页面反馈；减少歌手扎堆、同一录音跨平台重复和刚播放过的歌曲。
- 结果不包含任何用户歌单中已有的歌曲；参考歌单被排除、抽样没有选到的歌曲仍参与去重。LX推荐缓存升级为v5，保留筛选偏好，丢弃旧算法的候选缓存；保存参考歌身份和轮换计数以持续执行每首两首的配额。
- 取消、来源失败和缓存版本迁移保持已有可用结果；新模式不展示旧平台结果冒充软件推荐。
- AI 未启用参考开关时不发送画像；排序只接受真实候选 ID。
- 在隔离测试数据上检查性能与数据库迁移，不用用户真实播放行为做自动播放测试。

当前全量173项回归检查通过。新增覆盖整份列表的两首配额、超过20首的展示和播放队列、取消后清除临时预览、B站预览中的歌手补全保留至最终结果、旧分页缓存展开，以及 AI 候选补查和严格筛选。主进程及界面生产构建、全量 ESLint 检查通过；在独立 Electron 测试窗口实测两种模式的40首完整列表、底部滚动及宽窄窗口排版。此前阶段的公开歌曲样本已验证网易云和B站关联发现；此前QQ样本的20首、六个方向属于两首上限改动之前的记录。本轮使用隔离数据验证，未调用用户付费模型服务，未自动播放、切换音乐或写入人工收听记录。具体请求预算、缓存和样本限制见算法调研与AI升级说明。

## 9. 开源参考与本项目的取舍

- [Nuclear 的发现文档](https://github.com/nukeop/nuclear/blob/master/packages/docs/misc/discovery.md)：利用最近的队列歌曲作为发现上下文，并提供探索程度控制。本项目借鉴上下文和探索控制，结合用户歌单、实际收听和明确反馈。
- [Bili Music](https://github.com/Jmiao11/bili-music)：其 README 说明本地记录有效收听，并从收藏、歌单、听歌记录生成 AI 检索意图、重排真实结果。本项目借鉴有效收听和真实候选流程，再独立提供无需模型的软件推荐。

以上是流程参考，不表示复制其完整推荐算法，也不能据此保证推荐效果。当前个人播放器首先适合本地行为与元数据评分；在缺少多用户交互数据时，初版不采用需要该类数据的协同过滤训练方案。
